# 지킴톡 — 필수 원칙

**단톡방에서 당한 일을, 피해 학생 손으로, 신고할 수 있게.**

기능을 넣거나 뺄 때마다 먼저 묻는다: **이 학생이 도움을 받기까지 한 걸음이라도 줄어드나? 대화가 밖으로 새지 않나?**

1. **원문 그대로.** 메시지 글자를 고치거나 요약하거나 지어내지 않는다. 표시한 말에는 앞뒤 대화를 붙인다.
2. **찾기는 앱, 판단은 사람.** 보고서에 "가해자", "학교폭력이다" 같은 판단을 쓰지 않는다(테스트가 확인). 기록에 넣을지는 사람이 체크한다.
3. **대화는 기기 밖으로 안 나간다.** 서버·계정·분석 도구·외부 글꼴·CDN 없음(화면 테스트: 외부 요청 0건).
4. **위험 신호엔 도움부터.** 내 말에 자해 신호가 보이면 117·1388을 먼저 보인다. 그 말은 기록에 넣지 않는다.
5. **재지 않으면 믿지 않는다.** 학습·규칙 작성에 쓴 문장으로 성능을 말하지 않는다. `eval/RESULTS.md`에 나쁜 결과도 적는다.

## 개발 규칙

- 다듬기(normalize)는 파이썬(`model/normalize.py`)과 TS가 글자 하나까지 같아야 한다. 고치면 `tests/parity.json`을 다시 만들고 모델을 다시 학습한다.
- 규칙을 더하면 일상어 예외 테스트(`'보지 마'`, `'걸레질'` 등)에 일상 문장을 같이 더한다.
- 사용자에게 보이는 말은 쉬운 말로. "정밀도" ✗, "가해자" ✗.

```bash
npm test && npm run e2e && npm run measure
```
