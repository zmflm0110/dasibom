# 다시봄

> **찍어두고 잊은 것을, 필요한 순간에 다시 꺼내주는 앱**

인스타에서 좋은 걸 보면 스크린샷을 찍습니다. 그리고 다시는 안 봅니다.

사람들은 스크린샷을 찍는 순간 "저장했다"고 믿고 머릿속에서 지웁니다. 하지만 사진첩은
시간순으로 쌓이는 창고일 뿐이라 다시 찾을 방법이 없습니다. **스크린샷은 저장이 아니라
망각의 의식입니다.**

다시봄은 스크린샷 속 글자를 읽고, 무엇에 대한 것인지 이해하고, "저번에 그거"라는 말로
찾을 수 있게 만듭니다. 그리고 잊어버릴 때쯤 먼저 꺼내줍니다.

**전부 이 기기 안에서 돌아갑니다.** 사진은 개인정보의 정점이라, 한 장도 밖으로 내보내지
않습니다. OCR·임베딩·LLM 모두 로컬입니다. API 키도 계정도 필요 없습니다.

---

## 실제로 측정한 것

`python3 tests/benchmark.py` 로 언제든 재현할 수 있습니다 (스크린샷 53장 기준).

| 항목 | 결과 |
|---|---|
| 구어체 한국어 질의 1위 정답률 | **10/10** |
| 질의 응답 시간 (중앙값) | **118ms** |
| 스크린샷 수집 속도 | **0.12초/장** (50장 6초) |
| AI 이해 속도 | **1.9초/장** (백그라운드) |
| OCR 인식 (한국어) | 53/53 |
| 외부로 나간 데이터 | **0바이트** |

찾아낸 질의 예시 — 스크린샷 글자와 **한 글자도 겹치지 않는데** 찾습니다:

```
"몸 만들려면 뭐 했더라"      →  운동 루틴 저장
"밥 해먹을 때 참고할 것"     →  토마토 파스타 레시피
"엄마가 뭐 보낸다고 했는데"   →  엄마 카톡 (김치 택배)
"폰 케이스 사려고 봐뒀던 거"  →  아이폰 케이스
```

## 어떻게 동작하나

```
스크린샷
  ↓  Vision.framework          이미지 속 글자 읽기 (OCR, 온디바이스)
  ↓  Qwen2.5-3B (MLX)          무엇에 대한 것인지 이해 → 요약·분류·태그
  ↓  multilingual-e5-small     요약을 벡터로 (의미 검색용)
  ↓  정규식                    날짜 추출 (10월 3일, 11월까지…)
  ↓
검색  "저번에 그거"  |  먼저 꺼내주기  "2일 뒤 그 예약 있어요"
```

**분류를 사람이 정하지 않습니다.** AI가 스크린샷을 읽고 이름을 직접 짓습니다. 50장을
넣으면 카페추천·운동·레시피·면접준비·메신저·예약처럼 **그 사람이 실제로 모으는 것**에
맞는 분류가 생깁니다.

## 설치와 실행

```bash
./setup.sh --run
```

처음 실행 시 로컬 모델(약 2.2GB)을 받습니다. 그 뒤로는 네트워크가 없어도 동작합니다.
Apple Silicon Mac이 필요합니다 (MLX, Vision).

```bash
python3 -m clipmind.app        # 앱 실행
python3 tests/benchmark.py     # 측정치 재현
```

### 📱 폰에서 쓰기

사이드바의 "📱 폰에서 열기" → QR을 폰 카메라로 스캔하면 끝입니다. 같은 와이파이면
자동으로 연결되고, 폰 사진첩에서 스크린샷을 여러 장 골라 한 번에 올릴 수 있습니다.
"홈 화면에 추가"하면 앱처럼 아이콘도 생깁니다.

연결은 실행할 때마다 새로 생기는 6자리 PIN으로 보호됩니다. 같은 와이파이의 다른
기기가 그냥 들어올 수 없고, PIN 시도는 IP당 60초에 8회로 제한됩니다.

## 만들면서 측정으로 뒤집은 결정들

이 프로젝트에서 가장 값비쌌던 판단들은 전부 "해봤더니 아니었다"에서 나왔습니다.

**1. 손으로 짠 분류 규칙 → 로컬 LLM**
카테고리 10개를 정해놓고 키워드로 맞추는 방식이었습니다. 제가 정한 칸 밖의
스크린샷 6종으로 시험하니 전부 틀렸습니다 — 엄마 카톡을 "맛집"으로, 고양이
예방접종을 "쇼핑"으로 분류했습니다. 같은 입력에서 LLM은 6/6 맞혔습니다.

**2. 임베딩 유사도로 비슷한 분류명 병합 → 폐기**
"카페"와 "커피숍"을 묶으려 했는데, 짧은 한국어 라벨 12개의 66개 쌍이 전부
0.865~0.928 한 구간에 몰려 있었습니다. 경계선 자체가 없었고, 실제로 50장이
"전자제품" 한 칸으로 붕괴했습니다. 라벨 일관성은 LLM이 맡습니다.

**3. cross-encoder 리랭커 → 기본 OFF**
검색 순위를 고쳐줄 거라 기대했지만 오히려 악화시켰습니다(5/8 → 4/8). "운동"과
"요리" 정답을 서로 바꿔놨습니다. 기계번역 데이터로 학습돼 한국어 구어체에
약합니다. 영어·코드 질의에는 도움이 되어 플래그로 남겼습니다.

**4. 날짜만은 LLM이 아니라 정규식**
의미는 LLM이 잘하지만, 날짜는 틀린 값이 없는 값보다 나쁩니다 — 엉뚱한 날에
알림이 뜨니까요. 의미는 LLM이, 달력은 규칙이 맡습니다.

## 알려진 한계

- **폰 스크린샷은 자동으로 안 올라옵니다.** iOS는 어떤 앱(네이티브 포함)도 백그라운드에서
  사진첩이나 클립보드를 감시하지 못하게 막아둡니다. 그래서 "고르기" 동작 한 번이 필요합니다.
  이건 구현 부족이 아니라 플랫폼 제약입니다.
- **8GB RAM 기준 3B 모델이 상한입니다.** 더 큰 모델이면 분류명이 더 안정적이겠지만,
  OS·앱·임베딩 모델과 같이 못 올립니다. 대신 검증층으로 작은 모델의 드리프트
  (한자 전환, 스키마 되뱉기)를 잡습니다.
- **클릭 상호작용은 자동 검증을 못 했습니다.** 이 개발 환경에 macOS 전역 입력 자동화가
  없어서, 데이터·API·렌더링까지만 확인했습니다.
- **네이티브 iOS 앱은 아닙니다.** 폰 쪽은 로컬 네트워크로 접속하는 웹 앱입니다.
