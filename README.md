# ClipMind

**흘려보낸 것들을 다시 찾아주는 개인 기억 시스템.** 복사한 텍스트든, 인스타에서
찍어두고 잊어버린 아이디어 스크린샷이든 — 자동으로 분류하고, 이미지 속 글자까지
읽어서(OCR), 한국어로 물어보면 의미로 찾아준다. 전부 로컬에서, 외부 AI API 호출
없이 동작한다.

두 갈래로 들어온다:
- **복사** → 맥 클립보드를 실시간 감시해서 자동 저장
- **아이디어 스크린샷** → 폰에서 올리면 OCR로 글자를 읽어 검색 가능하게 만들고,
  며칠 지나 잊어버릴 때쯤 "💡 잊고 있던 아이디어"로 다시 꺼내준다

## 구조

```
복사 (NSPasteboard 폴링)
    -> classifier.py   규칙 기반 분류 (url/email/path/code[언어]/한국어·영어 텍스트)
    -> store.py        SQLite 저장 (내용, 분류, 캡처 당시 활성 앱, 임베딩)
    -> embeddings.py   다국어 문장 임베딩 (paraphrase-multilingual-MiniLM-L12-v2)
                        미설치 시 search.py가 TF-IDF로 자동 폴백
    -> search.py        의미 검색 (코사인 유사도) / 키워드 검색
    -> combine.py       여러 클립을 하나로 병합
```

## 설치

```bash
./setup.sh          # venv 만들고 필요한 패키지 전부 설치
./setup.sh --run    # 설치 후 바로 데스크톱 앱 실행
```

터미널이 낯선 사람도 `./setup.sh --run` 한 줄이면 끝나도록 만들었다. 직접
pip으로 설치하고 싶으면:

```bash
pip3 install -r requirements.txt
```

`sentence-transformers`가 없어도 전부 동작한다 (TF-IDF 폴백). 단, 이 경우
"로그인 코드 찾아줘" 같은 한국어 질의로 영어 코드를 찾는 진짜 의미/교차언어 검색은
안 되고, **질의와 문자열이 겹칠 때만** 찾아진다. 교차언어 의미 검색을 쓰려면
sentence-transformers가 필요하다 (설치 시 첫 실행에 모델 ~420MB 다운로드).

## 사용법

```bash
# 데몬 시작 (클립보드 감시)
python3 -m clipmind.cli start

# 최근 클립 목록
python3 -m clipmind.cli list --limit 20

# 의미 검색
python3 -m clipmind.cli search "JWT 토큰 발급하는 코드"

# 키워드(부분 문자열) 검색
python3 -m clipmind.cli search "FastAPI" --keyword

# 클립 전체 내용 보기
python3 -m clipmind.cli show 5

# 여러 클립을 하나로 합치기
python3 -m clipmind.cli combine 2 5 7

# 카테고리별 통계
python3 -m clipmind.cli stats

# 지금 어떤 앱을 보고 있는지에 따라 맥락 맞춤 추천 (코드 에디터면 code 카테고리로 좁혀 검색)
python3 -m clipmind.cli suggest
python3 -m clipmind.cli suggest "JWT 인증 관련 코드"
```

### 메뉴바 앱 (가벼운 대안, 네이티브 알림창 UI)

```bash
python3 -m clipmind.menubar
```

메뉴바에 📋 아이콘으로 뜨고, 백그라운드에서 0.5초 간격으로 클립보드를 감시한다.
"Recent" 하위 메뉴에서 최근 클립을 클릭하면 다시 클립보드로 복사되고, "Search…"로
의미 검색, "Suggest for current app"으로 맥락 추천을 바로 확인할 수 있다. UI는
macOS 기본 알림창(NSAlert) 그대로라 노션 스타일은 아니다 — 아래 데스크톱 앱 권장.

### 💡 아이디어 스크린샷 (인스타에서 찍어두고 잊어버리는 그것들)

"+ 추가" → "🖼 스크린샷 선택"으로 이미지를 올리면:
1. macOS Vision 프레임워크로 **로컬 OCR** (한국어/영어, 별도 설치 불필요)
2. 읽어낸 글자를 클립 내용으로 저장 → 텍스트 클립과 똑같이 **의미 검색**됨
   ("카페 창업 아이디어" 같은 말로 찾으면 그 스크린샷이 나옴)
3. 3일 이상 지난 것들을 앱 열 때 **"💡 잊고 있던 아이디어"** 배너로 다시 보여줌
   (한 번 보여준 건 뒤로 밀려서 같은 것만 반복되지 않음)

폰에서 하려면 아래 "폰에서 열기"로 연결한 뒤, 폰 사진 보관함에서 바로 고르면 된다.

**왜 자동으로 안 가져오나:** iOS는 어떤 앱(네이티브 포함)도 백그라운드에서 클립보드나
사진 보관함 변화를 몰래 감시하지 못하게 막아둔다. 그래서 "찍으면 자동으로 올라옴"은
원천적으로 불가능하고, 고르는 한 번의 동작이 필요하다.

### 📱 폰에서 열기 (같은 와이파이, Mac ↔ iPhone)

데스크톱 앱 사이드바의 "📱 폰에서 열기"를 누르면 QR 코드가 뜬다. 같은 와이파이에
연결된 폰 카메라로 스캔하면 자동으로 열리고 페어링까지 끝난다 — 아무것도 따로
설치할 필요 없이, 폰 브라우저(Safari/Chrome)에서 그대로 같은 노션 스타일 UI가
열린다. "홈 화면에 추가"하면 아이콘까지 생겨서 앱처럼 쓸 수 있다 (manifest.json +
apple-touch-icon 적용됨).

**진짜 네이티브 iOS 앱이 아니라 이걸 택한 이유:** 이 개발 환경에는 Xcode/iOS
시뮬레이터가 없어서 (`xcodebuild`/`simctl` 둘 다 불가 — command line tools만 설치됨)
네이티브 앱은 만들어도 직접 빌드해서 돌려볼 방법이 없었다. 대신 이미 만들어둔
로컬 웹 UI를 그대로 재사용하면 실제로 동작하는 걸 curl로 전부 검증할 수 있고,
사용자 입장에서도 App Store 설치 없이 QR 한 번으로 끝나서 오히려 더 간단하다.

**보안:** Flask를 `0.0.0.0`으로 열어서 같은 와이파이의 아무 기기나 두드릴 수 있게
되는 게 걱정이라, 페어링 없이는 `/api/*` 전부 401을 반환하도록 막았다
(`clipmind/pairing.py`). Mac 데스크톱 앱 자신(127.0.0.1)은 예외로 항상 신뢰하고,
그 외 기기는 앱 실행마다 새로 생기는 6자리 PIN을 한 번 증명해야 토큰을 받는다.
틀린 PIN은 IP당 60초에 8회로 속도 제한을 걸어뒀다. 실제로 다른 IP인 것처럼
curl로 미인증 401 → 오답 PIN 거부 → 정답 PIN으로 토큰 발급 → 그 토큰으로 LAN
요청 성공까지 전부 라이브로 검증함. 페어링 로직 자체는 pytest 스타일 단위
테스트 10건으로 별도 검증(`tests/test_pairing.py`).

### 데스크톱 앱 (권장 — 노션 스타일 UI)

```bash
python3 -m clipmind.app
```

Flask 로컬 서버(`clipmind/webapp.py`, 127.0.0.1:8765) + 순수 HTML/CSS/JS
프론트엔드(`clipmind/webui/`)를 pywebview 네이티브 창(WKWebView)에 띄운다.
외부 네트워크로는 전혀 나가지 않고, 전부 로컬에서 렌더링된다.

- 왼쪽 사이드바: 전체 + 카테고리별(색상 태그, 개수)
- 상단 검색창: 입력하는 대로(260ms 디바운스) 의미 검색
- ✦ 추천: 지금 최전면 앱 기준 맥락 추천 배너
- 각 클립 카드: 호버 시 복사/삭제 아이콘, 체크박스로 다중 선택 → 하단에 뜨는
  선택 바에서 "합치기 & 복사" (선택한 클립을 순서대로 합쳐 바로 클립보드에 복사)
- 라이트/다크 모드 자동 대응 (시스템 설정 따라감)

## 검증된 것 (실제로 돌려본 결과)

- 분류기: url/email/path/code(python/js/html/sql/shell/json)/한국어·영어 텍스트 15/15 케이스 통과.
- 실시간 캡처: `pbcopy`로 클립보드를 바꾸면 0.3~0.5초 내 감지, 분류, 활성 앱과 함께 SQLite에 저장됨을 확인.
- 의미 검색: "회의 일정" 질의가 "내일 오전 10시에 팀 회의..." 텍스트를 score 0.72로 정확히 1위로 찾음.
- 교차언어 검색: 한국어 질의("로그인 인증 토큰 발급하는 코드")가 영어 JWT 코드 스니펫을
  (문자열이 전혀 안 겹치는데도) top-3 안에서 찾아냄 — 진짜 의미 기반 임베딩이 동작함을 확인.
- 중복 억제: 동일한 내용을 연속으로 복사해도 한 번만 저장.

## 알려진 한계 (현실성 판단)

- **소규모 표본에서 랭킹이 흔들림.** MiniLM 기반 경량 모델이라 항목이 몇 개 안 될 때는
  관련 없는 항목이 1위로 오는 경우가 있었다 (예: 짧은 텍스트/이메일이 코드보다 위로 감).
  항목 수가 늘어날수록(문서가 많아질수록) 상대적 랭킹은 보통 개선된다 — 더 큰 실사용
  데이터로 재검증 필요.
- **활성 앱 감지는 GUI 세션에서만 의미 있음.** 터미널/헤드리스 컨텍스트에서 캡처하면
  `frontmostApplication()`이 `loginwindow` 등 엉뚱한 값을 반환할 수 있음 — 실제 데스크톱
  세션(사용자가 직접 로그인해서 Dock이 떠 있는 상태)에서 재확인 필요.
- **상시 실행(로그인 시 자동 시작)은 아직 없음.** `clipmind start`를 수동 실행해야 함.
  다음 단계로 launchd plist를 붙이면 로그인 시 자동 시작 가능 (시스템 자동시작 항목을
  건드리는 작업이라 별도 확인 후 진행 예정).
- **"현재 작업 맥락 보고 추천"은 기초 수준까지만 구현됨** (`clipmind suggest`).
  현재 최전면 앱 이름만으로 code/기타 맥락을 추정해 검색 범위를 좁힘 — 실제 VS Code 파일
  내용이나 커서 위치를 읽는 건 접근성 권한이 필요한 다음 단계이고 아직 없음.
- **메뉴바 앱 있음** (`clipmind.menubar`, rumps 기반) — 실제로 띄워서 스크린샷으로 아이콘
  노출 확인, GUI 세션에서 실제 활성 앱 이름("터미널")까지 정확히 기록되는 것까지 라이브로
  검증함.
- **노션 스타일 데스크톱 앱 있음** (`clipmind.app`) — 실제로 띄워서 창 단위 스크린샷으로
  검증. 그 과정에서 진짜 버그 하나를 찾아 고쳤다: `.empty-state`/`.select-bar`가 CSS에
  `display: flex`를 직접 선언해서 브라우저 기본 `[hidden]{display:none}` 규칙과
  우선순위가 같아지고, 나중에 로드된 내 스타일이 이겨버려 `hidden` 속성이 무시되고
  있었음 (클립이 8개 있는데도 "클립 없음" 문구가 같이 떠 있었음) → 전역
  `[hidden]{display:none!important}` 규칙 추가로 수정, 스크린샷으로 재확인함.
  단, 이 환경에 macOS 전역 마우스/키보드 자동화 도구가 없어 (accessibility 클릭이
  WKWebView에는 실제 마우스 이벤트로 전달되지 않음을 확인함) 체크박스 선택·검색창
  타이핑 같은 실제 클릭 상호작용은 자동으로 검증하지 못했다 — 데이터 렌더링/스타일/
  API 경로만 확인됐고, 클릭 동작 자체는 사용자가 직접 확인 필요. Chrome 확장도 이
  세션엔 연결이 안 돼 있어 브라우저로 우회 검증도 못 했다 — "📱 폰에서 열기" 모달의
  실제 클릭 동작(QR 렌더링, PIN 입력 폼)도 같은 이유로 코드 리뷰 수준까지만 검증됨.
- **검색 리랭커**(`reranker.py`, cross-encoder) — "로그인 인증 토큰 발급 코드" 질의에서
  이전엔 무관한 HTML이 1위였는데, 리랭커 적용 후 실제 JWT 코드가 1위로 오는 것을
  실측으로 확인. `tests/test_store_search.py`에서 top-1 정확도까지 검증.
- **실제 편집 파일 기반 맥락 인식** — 앱 이름뿐 아니라 최전면 창 제목(Quartz
  윈도우 API)에서 파일 확장자를 읽어 언어까지 추정, 같은 언어 코드 클립을 우선
  추천. Screen Recording류 별도 권한 요청 없이 창 제목이 읽히는 것을 이 세션에서
  확인함(권한 상태는 macOS 버전/설정에 따라 다를 수 있음 — 안 읽히면 앱 이름
  기반 추천으로 자동 폴백).
