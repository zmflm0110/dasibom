# 찍풀 — 필수 원칙

## 모토

**찍기만 하던 판서를, 떠올리는 복습으로.**

## 누구를 위해

- **주 사용자:** 수업 끝에 판서를 찍고 다시 안 보는 중·고등학생. 필기는 귀찮고, 폰은 늘 손에 있다.
- **곁의 사람:** "찍기만 하지 말고 봐라"라고 말하는 선생님.

기능을 넣거나 뺄 때마다 먼저 묻는다: **이 학생이 판서를 한 번이라도 더 떠올리게 되나?**

## 원칙 (기능 요청보다 우선)

1. **정답은 판서 그 자체.** 풀 때 여는 것은 사진 픽셀이다. OCR 글자·AI 글자로 정답을 만들지 않는다. 판서에 없는 말을 지어내지 않는다.
2. **찍고 10초.** 수업 끝 쉬는 시간에 끝나야 한다. 찍은 뒤 저장까지 기본 누름 1번(과목은 시간표로, 빈칸은 추천으로). 새 기능이 이 누름을 늘리면 넣지 않는다.
   - 지킴: 화면 테스트("찍으면 과목이 저절로, 빈칸이 추천된다").
3. **읽기보다 떠올리기, 몰아서보다 간격.** 복습 화면은 언제나 "먼저 떠올리고, 그다음 정답".
4. **사진은 폰 밖으로 안 나간다.** 계정·서버·클라우드·분석 도구 없음. 한 번 연 뒤로 인터넷 없이 된다.
   - 지킴: 화면 테스트("밖으로 나간 요청 0건", "오프라인에서도").
5. **재지 않으면 믿지 않는다.** 개발용에서만 규칙을 고치고, 시험용은 마지막에 한 번 잰다. 나쁜 결과도 `eval/RESULTS.md`에 그대로 적는다.

## 하지 않을 것

- AI 문제·요약 생성(지어낸 내용)
- 사진을 서버로 보내는 모든 기능
- 점수 경쟁·순위(복습은 남과 겨루는 게 아니다)

## 개발 규칙

- `src/core`는 의존성이 없다. 추천 규칙을 고치면 `npm test`(회귀 방지 포함)와 `npx tsx eval/suggest-measure.ts`를 같이 돌린다.
- 학생에게 보이는 말은 쉬운 말로('인출 연습' ✗ → '떠올려 보기').

## 명령

```bash
npm test          # 단위 테스트
npm run e2e       # 화면 테스트(Chromium 헤드리스)
npm run dev       # 개발 서버
npm run measure   # OCR·추천 측정(개발용)
```
